💡 Purpose of Stage 1

The 1B Dense model serves as the foundation for all subsequent stages. It establishes:

  • Basic language understanding and generation capabilities
  • Stable weight distributions that will be copied to experts
  • A checkpoint that can be verified before MoE conversion
  • The FFN weights become the template for all 8 experts in Stage 2

Copy Dense FFN to All 8 Experts

Each expert starts as an identical copy of the 1B Dense FFN. This is "explosion" (1→8).

2

Initialize Fresh GSA Router

New router with 4 heads × 64d projection. Initialized to route uniformly across all experts.

3

Small Gaussian noise to expert weights for symmetry breaking during training.

4

Train to Learn Routing

Router learns which tokens go to which experts. Experts specialize through gradient updates.

⚠️ Lossless Guarantee

At initialization (before noise): All experts identical + weights sum to 1 → output_MoE = output_Dense. The model starts from the exact same point.

❓
Why 8 Routed Experts?

Rationale for 8 Experts at 3B Scale

  • Minimum for meaningful specialization - 8 can capture broad categories (code, math, etc.)
  • Stability first - Fewer routing decisions = less potential instability
  • Learning objective - Stage 2 is about learning ROUTING, not maximizing capacity
  • Prepares for scaling - Same 8 experts will grow bigger in Stage 3

4

Continue Training

Same routing patterns preserved! Experts refine their specializations at larger capacity.

✅ Why Keep Same Experts?

The 8 experts have already learned their specializations during 3B training. Scaling dimensions makes each expert MORE capable without changing what they specialize in. Routing knowledge is preserved!

❓
Why Not Add More Experts Yet?

Benefits of Scaling Dimensions First

  • Routing stability - Adding experts requires learning new routing; scaling dims doesn't
  • Expert capacity - 8 larger experts can handle more nuanced specialization
  • Gradient preservation - Interpolation preserves learned weights better than expert splitting
  • Prepares for 70B - 8 high-capacity experts become the template for 64-expert explosion
  • Verification point - Can validate 8B MoE before massive 70B expert expansion

Expert E1 → {E1.1, E1.2, ..., E1.8}. Each child starts identical to its parent.

New GSA router with 64 expert keys. Can optionally warm-start from 8-expert router with hierarchical init.

With 64 experts, need more active experts per token for coverage. 4/64 = 6.25% active.

5

Train with Loss-Free Load Balancing

Bias-only adjustment. Router learns fine-grained 64-expert routing patterns.

❓
Why 64 Experts Now?

Rationale for 64 Experts at 70B Scale

  • Clean hierarchy - 8 parents × 8 children = 64. Preserves specialization structure.
  • Parameter budget - 70B / 8B ≈ 9×. Mostly comes from 8× more experts.
  • Data diversity match - 50-100 distinct patterns in language; 64 matches well.
  • Literature validated - DeepSeek-MoE, Mixtral use similar expert counts.
  • Hardware friendly - 64 = power of 2, efficient GPU scheduling.
❓
Why Top-4 Active?

Rationale for 4 Active Experts

  • Capacity balance - 4 experts provide enough capacity per token
  • Specialization + coverage - Can combine 4 different sub-specialties
  • Compute budget - 4/64 = 6.25% active (reasonable overhead)
  • Adaptive range - Can vary 2-6 based on GSA confidence score
  • Preserves hierarchy - Often selects 1-2 from each parent group
