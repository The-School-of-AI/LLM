# Curriculum Tokenizer

This module provides the `tokenize_curriculum.py` pipeline for tokenizing
Curriculum Learning datasets from a T3 coreset index into binary shard files
compatible with spdl / Megatron-style training loaders.

---

## Architecture — 2-Level T3 → T1

The pipeline uses a **2-level architecture**. T2 is bypassed entirely.

```
T3 Coreset Parquet                   T1 Raw-Text Parquets
(manifest / index)         →         (source documents)
  chunk_id                               id  (matched against chunk_id)
  t1_file_path                           text
  band                                   …
  domain
```

Each T3 coreset file is a manifest whose rows identify exactly which
documents from T1 survived quality filtering. The script:

1. Groups T3 rows by `t1_file_path` to minimise redundant T1 downloads.
2. Downloads each T1 parquet and filters to only the `chunk_id` rows.
3. Tokenizes the matching text documents.
4. Packs tokens into fixed-size blocks and flushes binary shards.

---

## Output Structure

```
<dst-uri>/
├── progress_state.json              ← resume tracker (updated after each batch)
├── manifest.json                    ← global summary (written on clean completion)
└── shards/
    ├── shard_001/
    │   ├── tokens.bin               (packed uint32 blocks, block_size tokens each)
    │   ├── tokens.idx               (spdl-compatible binary byte offsets)
    │   └── metadata.json            (per-shard stats + curriculum metadata)
    ├── shard_002/
    │   └── …
    └── shard_NNN/
```

Shard numbering is **global across all coreset batches**. The `metadata.json`
inside each shard retains `source_file` (the originating coreset URI) for full
traceability. For parallel runs (`--file-parallelism N`), an atomic counter shared
across workers ensures globally-unique shard numbers are assigned at write time —
no post-processing step is required.

### `metadata.json` fields (per shard)

| Field | Description |
| :--- | :--- |
| `format` | `"megatron_bin_idx"` |
| `idx_format` | `"spdl_v1"` |
| `token_dtype` | `"uint32"` |
| `block_size` | Tokens per block |
| `vocab_size` | Tokenizer vocabulary size |
| `pad_token_id` / `eos_token_id` | From the loaded tokenizer |
| `num_blocks` / `total_tokens` | Block and token counts |
| `tokenizer_hash` | SHA-256 over `tokenizer.json` + `special_tokens_map.json` |
| `tokenizer_version` | Value of `--tokenizer-version` |
| `band` / `band_distribution` | Dominant band and full distribution |
| `domain` / `domain_distribution` | Dominant domain and full distribution |
| `stage` | Training stage (`--stage`) |
| `rows_input` / `rows_with_eos` / `rows_dropped` | Row-level audit trail |
| `created_at` | UTC timestamp |

## Running the Tokenizer

### Minimal command (S3)

```bash
python tokenize_curriculum.py \
    --coreset-uri  "s3://your-bucket/coresets/stage1/" \
    --dst-uri      "s3://your-bucket/tokenized/stage1/" \
    --tokenizer-path ../tsai_131k_tokenizer
```

### Minimal command (local)

```bash
python tokenize_curriculum.py \
    --coreset-uri  "dataset/final/small/t3/" \
    --dst-uri      "dataset/final/small/tok_out" \
    --tokenizer-path ../tsai_131k_tokenizer \
    --t1-base-uri  "dataset/final/small/t1"
```

`--coreset-uri` accepts a single `.parquet` file **or** a folder. When a folder
is given, every `.parquet` file inside it is processed as a separate batch.

### Full command (all options)

```bash
python tokenize_curriculum.py \
    --coreset-uri       "s3://your-bucket/coresets/stage1/" \
    --dst-uri           "s3://your-bucket/tokenized/stage1/" \
    --tokenizer-path    ../tsai_131k_tokenizer \
    --t1-base-uri       "s3://t1-dataacquisition-datasets/processed_dataset/normalized_data" \
    --block-size        4096 \
    --shard-size-mb     512 \
    --num-proc          8 \
    --file-parallelism  4 \
    --stage             1 \
    --tokenizer-version v1 \
    --drop-remainder \
    --tmp-dir           /tmp/tok_tmp
```

---

## Available Arguments

| Argument | Description | Default |
| :--- | :--- | :--- |
| `--coreset-uri` | **[Required]** S3 URI or local path to a T3 coreset `.parquet` file or folder | — |
| `--dst-uri` | **[Required]** Destination S3 URI or local folder | — |
| `--tokenizer-path` | Path to a HuggingFace tokenizer directory. If omitted, looks for `tsai_131k_tokenizer/` next to the script | `None` |
| `--t1-base-uri` | Base URI for T1 raw-text parquets. Full T1 path is constructed as `t1_base_uri + "/" + t1_file_path` (from T3 column). Override to a local folder for testing. | `s3://t1-dataacquisition-datasets/processed_dataset/normalized_data` |
| `--block-size` | Tokens per packed block | `4096` |
| `--shard-size-mb` | Target shard size in MB | `512` |
| `--num-proc` | HuggingFace tokenizer subprocesses per worker (internally capped at 4) | `8` |
| `--file-parallelism` | Number of coreset batch files to process concurrently (uses `multiprocessing` spawn) | `1` |
| `--stage` | Training stage number — written to shard `metadata.json` | `1` |
| `--tokenizer-version` | Tokenizer version string — written to shard `metadata.json` | `"v1"` |
| `--drop-remainder` | Drop the tail buffer if it is shorter than `--block-size`. Default is to pad with the tokenizer's PAD token. | `False` |
| `--tmp-dir` | Temporary working directory for downloads and shard assembly | System temp |

## Tail Handling and Data Integrity

By default the final incomplete buffer is **padded** to exactly `--block-size`
using the tokenizer's `pad_token_id`. The log will show:

```
[Info] Padded final block with N PAD tokens (preserved M tokens).
```

Pass `--drop-remainder` to discard the tail instead. The log will show:

```
[Warning] Dropped remainder: N tokens (approx M rows dropped/truncated).
```

Both paths write `rows_input`, `rows_with_eos`, `rows_dropped`, and
`tokens_dropped` to `metadata.json` for a full audit trail.

---

## Interrupt Handling and Resume

The pipeline registers `SIGTERM` / `SIGINT` handlers and polls the EC2 IMDS
endpoint every 5 s for Spot termination notices. On receiving a signal:

- The current T1 download finishes; no new T1 files are started.
- Partially accumulated (un-flushed) blocks are discarded.
- Only fully uploaded shards are retained.
- `progress_state.json` is updated with the list of completed coreset files.

Re-running with the **same arguments** automatically skips completed files and
resumes from where processing stopped.

## Validating Output Shards

`validate_shards.py` runs an 8-point checklist on every shard under a
given output directory:

1. Required files present: `tokens.bin`, `tokens.idx`, `metadata.json`
2. `tokenizer_hash` matches the live tokenizer
3. `eos_token_id`, `pad_token_id`, `vocab_size` match the live tokenizer
4. `total_tokens == file_size / 4`
5. `len(idx_offsets) - 1 == num_blocks`
6. `rows_dropped + rows_with_eos == rows_input`
7. `max(token_id) < vocab_size`
8. `band`, `domain`, `stage` are non-empty in `metadata.json`

### Usage

Pass the **output root** (the parent of `shards/`) as `--shards-dir`. The
validator looks for shards under `<shards-dir>/shards/shard_NNN/`.

```bash
# Validate after tokenize_curriculum.py completes (sequential or parallel)
python validate_shards.py \
    --shards-dir   dataset/final/small/tok_out \
    --tokenizer-path ../tsai_131k_tokenizer

# Verbose output + stop on first failure
python validate_shards.py \
    --shards-dir   dataset/final/small/tok_out \
    --tokenizer-path ../tsai_131k_tokenizer \
    --verbose \
    --fail-fast
```

Exits with code `0` if all shards pass, `1` if any fail.

## Flat Global Shard Output (Updated Layout)

The output layout has been updated from per-batch subdirectories to a single
flat `shards/` directory with globally-continuous numbering.

### New output structure

```
<dst-uri>/
├── progress_state.json              ← resume tracker (updated after each batch)
├── manifest.json                    ← global summary (written on clean completion)
└── shards/
    ├── shard_001/
    │   ├── tokens.bin
    │   ├── tokens.idx
    │   └── metadata.json            ← source_file field preserves traceability
    ├── shard_002/
    ├── shard_003/
    ├── shard_004/                   ← second coreset batch continues from here
    └── shard_NNN/
```

Shard numbering is **global across all coreset batches** — there are no
intermediate per-batch subdirectories. The `metadata.json` inside each shard
retains `source_file` (the originating coreset URI) for full traceability.

### Resume behaviour

`progress_state.json` tracks completed batches, the global shard counter, and
any interrupted state:

```json
{
  "completed": ["uri_A", "uri_B"],
  "interrupted": [
    {"uri": "uri_C", "shard_start": 9, "shard_end": 10}
  ],
  "next_shard_idx": 9,
  "failed": [],
  "last_updated": "2026-03-06T10:00:00Z"
}
```

| Key | Set when |
| :--- | :--- |
| `completed` | A batch finished without interruption |
| `interrupted` | A SIGTERM/SIGINT fired mid-batch (sequential mode); partial shards are cleaned up and the batch is re-queued on next run |
| `next_shard_idx` | After every completed batch; ensures the global counter is continuous across runs |

Re-running with the same `--dst-uri` is safe and idempotent.

### Sequential vs parallel

| Mode | Output layout | Global numbering |
| :--- | :--- | :--- |
| `--file-parallelism 1` (default) | `shards/shard_NNN/` flat | Yes — automatic via sequential counter |
| `--file-parallelism N` | `shards/shard_NNN/` flat | Yes — automatic via atomic `Manager.Value` counter shared across all workers |

### Validating the new layout

Pass the `--dst-uri` root (the parent of `shards/`) to `validate_shards.py`:

```bash
python validate_shards.py \
    --shards-dir   dataset/final/small/tok_out \
    --tokenizer-path ../tsai_131k_tokenizer
```

The validator now looks for shards under `<shards-dir>/shards/shard_NNN/`
instead of the old two-level `<shards-dir>/<coreset>/shard_NNN/` layout.
