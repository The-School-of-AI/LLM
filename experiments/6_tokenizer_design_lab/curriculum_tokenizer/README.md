# Curriculum Tokenizer

This module provides the `tokenize_curriculum.py` script for tokenizing bespoke Curriculum Learning datasets across Amazon S3.

## Overview
Unlike bulk tokenizers that process an entire data bucket indiscriminately, the curriculum tokenizer takes a **Coreset file** as its input. 
A Coreset acts as an instruction manual (manifest) defining exactly which chunks of data from a raw S3 bucket survived your quality filtering. The script aggressively maps these `source_url`s and `chunk_id`s to the raw Parquet files, tokenizes the specific approved rows, and writes exact 512MB binary shards back to a cleanly organized destination S3 prefix.

## Output Structure
To preserve lineage and prevent messy buckets, the script natively organizes the exact 512MB chunks into isolated subfolders named after the Coreset instruction file that created them:

```text
s3://<dst-bucket>/<dst-prefix>/
│
├── batch001/                              <-- Generated by Coreset "batch001.parquet"
│   ├── shard_000/
│   │   ├── tokens.bin                     (Exactly 4096-token packed blocks)
│   │   ├── tokens.idx                     (spdl binary byte offsets)
│   │   └── metadata.json                  (Pad count, stats)
│   ├── shard_001/
│   │   ├── ...
```

## How to Setup and Run

If you are running this on a remote AWS EC2 instance (recommended for large scale processing), you must first connect to it (Step 1) and then perform all subsequent steps (Steps 2-5) within the active SSH session. 

If running locally on your own PC, skip Step 1 and start directly from Step 2.

### 1. Connect to AWS EC2 via SSH (Optional, for remote processing)

Open your local terminal (Powershell, Command Prompt, or Terminal) and connect using your `.pem` key file and the EC2 instance's IP address:

```bash
# Example SSH command:
ssh -i "path/to/your-key-pair.pem" ubuntu@ec2-XXX-XXX-XXX-XXX.compute-1.amazonaws.com
```

### 2. Clone the Repository and Navigate to the Directory

Open your local terminal (Powershell, Command Prompt, or Terminal) and run the following commands to get the required code:

```bash
git clone https://github.com/The-School-of-AI/LLM.git
cd LLM
git fetch --all
git checkout P06_Tokenizer_Design_Lab
cd experiments/6_tokenizer_design_lab/curriculum_tokenizer
```

### 3. Create and Activate Virtual Environment

It is recommended to run this script within a Python virtual environment.
First, create the virtual environment from your project folder:
```bash
python -m venv venv
```

Next, activate it depending on your operating system:

**On Windows:**
```bash
venv\Scripts\activate
```

**On macOS and Linux:**
```bash
source venv/bin/activate
```

### 4. Install Dependencies

Once the environment is active, install the required dependencies (such as boto3, pandas, datasets, transformers) or simply use the provided `requirements.txt`:
```bash
pip install -r ../requirements.txt
# or manually: pip install boto3 pandas datasets transformers
```

### 5. Run the Script

Now you are ready to execute the tokenizer script.

#### Standard Command (Using Default Options)
If your Coreset file has columns named exactly `source_url` and `chunk_id`, and your Raw S3 files have an ID column exactly named `id`, you can run the minimal command:

```bash
python scripts/curriculum_tokenizer/tokenize_curriculum.py \
    --coreset-uri "s3://t2-datacurriculum-353/coreset_outputs/coresets/1B/" \
    --dst-bucket "YOUR_OUTPUT_BUCKET_NAME" \
    --dst-prefix "coreset_outputs/coresets/1B/tokenized"
```

*Note: `--coreset-uri` can be a single `.parquet` file URL or a folder prefix (e.g., `.../1B/`). The script will auto-detect a folder prefix and seamlessly batch-process **every single Coreset parquet file** found inside it automatically.*

### Advanced Command (Explicit Mappings)
If your data science team used different column names, or you want to maximize CPU speed:

```bash
python scripts/curriculum_tokenizer/tokenize_curriculum.py \
    --coreset-uri "s3://YOUR_INPUT_BUCKET/manifests/batch002.parquet" \
    --url-col "my_s3_url_column" \
    --coreset-id-col "good_chunk_id" \
    --src-id-col "internal_id" \
    --text-col "cleaned_text" \
    --dst-bucket "YOUR_OUTPUT_BUCKET_NAME" \
    --dst-prefix "tokenized_output_folder/" \
    --num-proc 16
```

## Available Arguments

| Argument | Description | Default |
| :--- | :--- | :--- |
| `--coreset-uri` | **[Required]** S3 URI to either a single Coreset `.parquet` file or an S3 prefix folder containing multiple. | None |
| `--dst-bucket` | **[Required]** The destination S3 bucket name. | None |
| `--dst-prefix` | **[Required]** The destination S3 prefix to create the organized subfolders in. | None |
| `--url-col` | The column name in the Coreset detailing the S3 path of the Raw Dataset | `'source_url'` |
| `--coreset-id-col`| The column name in the Coreset containing the permitted Chunk ID | `'chunk_id'` |
| `--src-id-col` | The column name in the Raw Dataset to match against the Chunk ID | `'id'` |
| `--num-proc` | Number of concurrent CPU workers to use. Set to `16` or `32` for EC2 speed. | `8` |
| `--drop-remainder`| Flag: Instead of padding the final incomplete block of a run with `131074`, silently truncate and drop it (logs exactly how many tokens were dropped). | `False` (Defaults to safe padding) |

## Tail Padding and Data Integrity
By default, the script strictly enforces `Output EOS Count == Input Coreset Rows`. Because mathematical 4096-block boundaries rarely align perfectly with the chaotic length of English sentences, the pipeline will naturally "pad" the very final, incomplete block of a dataset stream with `131074` (`PAD`) tokens to cleanly reach exactly 4096.

This keeps training model shapes perfectly uniform while guaranteeing zero silent row truncation. You will see an informational log `[Info] Padded final block with X PAD tokens` upon completion.
